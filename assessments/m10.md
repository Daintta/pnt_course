# Module 10 assessment: Applied PNT Engineering (Capstone)

## order
Put the first steps of the repeatable applied PNT engineering method in order.
1. Define the mission and operating context
2. Identify the PNT dependency chain
3. Define consequences of unavailable, degraded, stale or wrong PNT
4. Derive measurable requirements
5. Define the threat and failure model
6. Design the architecture
> Sources and mechanisms are selected because they address requirements and failure modes, not because they are fashionable.

## single
The coastal surveillance craft analysis shows route following, sensor geolocation and event correlation all depend on PNT. Why is "the craft needs GPS" an inadequate requirement?
- Because GPS is not available at sea.
* Because different mission functions consume different PNT properties and have different consequences when those properties become unreliable.
- Because the craft only needs timing.
- Because GPS cannot be used by autonomous platforms.
> A dependency analysis per mission function reveals what capability, performance and consequence each function actually has.

## match
Match each craft mission function to the PNT information it relies on.
- Route following = Position, velocity and heading
- Sensor geolocation = Position, time and orientation
- Event correlation = Accurate time
- Operator awareness = PNT state and integrity
> Different functions consume different combinations of PNT, with different consequences if wrong.

## single
Which requirement best passes the capstone "requirement quality check"?
- "The craft shall have good navigation."
* "A source inconsistency capable of causing more than 15 m position error shall be detected and declared within 5 s under defined test conditions."
- "The craft shall use the best available receiver."
- "Navigation shall be resilient to interference."
> A good requirement is observable, has a measurable threshold, defined conditions and duration, an identified consumer and a traceable rationale.

## single
The craft has two GNSS receivers sharing one antenna, one power converter and one navigation computer. How should this be assessed?
- It is fully resilient because it has hardware redundancy.
* It has hardware redundancy, but a single antenna, RF, power or software fault could defeat both paths.
- It is resilient because the receivers are from different vendors.
- It only needs a second antenna to become fully independent.
> Whenever you see "backup", ask: backup against which failure? Then trace antenna, power, software, network, clock and other dependencies.

## single
Requirement PNT-07 states that loss of the primary communications link shall not remove the craft's local navigation capability. What does it protect against?

## multi
Why is the candidate architecture stronger than "two GNSS receivers"?
* It separates source acquisition from trust decisions.
* It monitors health and consistency before fusion.
* It propagates uncertainty and integrity state to the application.
* It contains explicit mode-management and recovery logic.
- It uses the largest possible number of GNSS constellations.
> Its strength comes from complementary sources plus explicit integrity management, not source count.

## truefalse
Redundancy without fault isolation can make deception worse.
= true
> A fusion algorithm that keeps weighting a plausible but corrupted source can produce a smooth, precise-looking and incorrect solution.

## order
Put the stages of handling plausible-but-wrong GNSS in order.
1. Independent measurements begin to disagree with the GNSS solution
2. The integrity function evaluates residuals, dynamics and health indicators against thresholds
3. GNSS is declared suspect
4. Suspect measurements are isolated from the operational solution
5. The PNT manager changes mode and exposes integrity state and uncertainty
6. GNSS remains quarantined until revalidation criteria are met
> A design that only detects complete signal loss can fail dangerously in this case.

## match
Match each weak capstone approach to the better engineering response.
- "If GPS fails, switch to INS." = Specify detection, failover, uncertainty growth and degraded-mode thresholds
- "Sensor fusion makes it resilient." = Define health monitoring, FDI/FDE and integrity-aware fusion
- "The system passed the demo." = Use traceable IADT evidence and negative and degraded testing
- "GNSS has recovered, switch back." = Use quarantine, revalidation and controlled reintegration
> Each weak approach hides a missing trigger, bound, monitor, test or recovery criterion.

## single
Which verification approach fits requirement PNT-04 ("a suspect source shall not contribute to the operational solution")?
- Demonstration of nominal operation only.
* Inspection plus test: force a source into the suspect state and check fusion inputs, source state and PNT output.
- Analysis of satellite geometry.
- A field trial with no instrumentation.
> Inspection shows how exclusion is implemented; test shows the runtime behaviour when the source becomes suspect.

## single
Why is "resilient PNT" too broad for an assurance claim?
- Because resilience cannot be assured at all.
* Because a defensible claim must state the mission, environment, threat or failure conditions, performance envelope and supporting evidence.
- Because assurance only applies to timing.
- Because it is a trademark.
> A pile of test reports is not an assurance case. Assurance explains why the evidence is sufficient for bounded claims.

## single
A supplier offers an emerging LEO-based source with strong headline figures but little evidence from your operating environment. What is an appropriate bounded conclusion?
- Adopt it immediately as the primary source.
- Reject it permanently because it is new.
* Classify it as suitable now, suitable only for trial or augmentation, or insufficiently evidenced for the role, and state what evidence would change that.
- Accept it if the supplier describes it as "next-generation".
> Technology readiness is not mission readiness. Evidence of environment, integration, support, security and failure behaviour is needed.

## single
A customer says "we need resilient timing even if GPS is jammed" for a 72-hour deployable command post. What should the engineering response begin with?
- Choosing a rubidium clock product.
* Mission and dependency analysis: identify timing consumers, criticality, consequences and the upstream timing chain.
- Writing the verification matrix.
- Adding a second GPS receiver.
> Do not begin by choosing a product. Requirements, threats and architecture follow from the mission and dependency analysis.
