# Module 07 assessment: Resilient PNT Engineering

## single
Which of these is an engineering resilience requirement rather than a technology statement?
- "Fit a backup GPS receiver."
- "Use GPS, Galileo and BeiDou."
* "Maintain horizontal position within 20 m for 15 minutes after loss of trusted GNSS, with a warning within 5 seconds if the bound cannot be maintained."
- "The system shall be resilient."
> A requirement defines the capability that must survive, its performance, duration and detection behaviour.

## match
Match each concept to its example.
- Redundancy = Two GNSS receivers
- Diversity = GNSS plus terrestrial radio PNT
- Dissimilarity = GNSS radio ranging plus inertial dead reckoning plus terrain matching
- Independence = A timing path with a separate reference, transport, power and local holdover
> Redundancy is necessary but not sufficient. Resilience improves when it is combined with diversity, dissimilarity and genuine independence.

## match
Match each resilience function to an illustrative example.
- Resistance = Robust installation and hardened configuration
- Detection = Integrity monitoring and cross-source comparison
- Response = Excluding suspect data and entering a degraded mode
- Recovery = Revalidating the returning source before controlled reintegration
> Passive resistance reduces harm; active detection, response and recovery preserve and restore trusted capability.

## single
A GNSS receiver is outputting coordinates at the expected rate. Why might a resilient architecture still refuse to use them?
- Because receivers should never be used when they are available.
* Because "available" is not the same as "healthy": the data may be stale, inconsistent, implausible or outside demonstrated conditions.
- Because fusion algorithms reject all GNSS data by default.
- Because coordinates are not PNT information.
> Each source should be monitored for freshness, quality, uncertainty, plausibility, consistency and configuration before fusion.

= false
> Detection is not attribution. Safe behaviour should not depend on immediate root-cause attribution.

## order
Put the resilient PNT modes in the order a platform would move through them during a GNSS outage that becomes progressively worse and then clears.
1. NORMAL
2. DEGRADED
3. RESTRICTED
4. UNAVAILABLE / SAFE
5. RECOVERY / REVALIDATION
6. NORMAL RESTORED
> Each mode has defined entry conditions and behaviour; recovery requires revalidation before normal operation is restored.

## single
What does a supervisory PNT manager do?
- Selects whichever source advertises the smallest accuracy figure.
* Controls source enablement, health state, mode transitions, failover, holdover, degraded operation, alerts and recovery criteria.
- Replaces the need for source monitoring.
- Only logs data for later analysis.
> It manages behaviour across the whole chain, not simply picking the most accurate-looking source.

## multi
When designing a failover transition, which should be defined?
* Which source becomes authoritative
* How state continuity is maintained without an unsafe position or time jump
* What uncertainty applies immediately after transition
* What mode status and restrictions are exposed to the application
- The paint colour of the backup unit

## single
In a deception scenario, GNSS remains available but diverges from INS, odometry and map constraints. What must fusion NOT do?
- Quarantine GNSS while the anomaly is assessed.
* Simply average or compromise between the suspect GNSS and the independent sources.
- Alert the application with a suspect-source state.
- Maintain a degraded solution with explicit uncertainty.
> Averaging blindly lets a bad source pull the solution away from truth. A robust architecture must distrust a source that is still producing data.

## single
Why is hysteresis used in recovery criteria?
- To speed up reintegration of any returning source.
* To stop a marginal source repeatedly entering and leaving the solution, which creates unstable mode flapping.
- To increase the holdover duration of the clock.
- To reduce the number of sources required.
> Using different criteria or persistence periods for failure and recovery prevents unstable behaviour.

## match
Match each recovery objective to its meaning.
- Recovery point objective = Maximum tolerable PNT error or state loss during disruption
- Recovery time objective = How quickly acceptable service must be restored
> Both are application-specific engineering measures derived from the mission, not universal constants.

## single
What is the key architectural lesson from the NPLTime timing example?
- One highly accurate distribution path is enough.
* Independent feeds plus local holdover clocks and monitoring reduce reliance on a single distribution path.
- Timing resilience only requires a GNSS receiver.
- Holdover provides unlimited backup.
> NPL describes independent PTP feeds from separate hydrogen masers plus a local caesium clock for extended holdover at each node.

## single
During a design review, which question most directly exposes hidden single points of failure?
- How many sources does the design have?
* For every backup, what does it share with the primary, and is that shared element monitored, redundant or accepted as residual risk?
- Which source is the most accurate?
- How much does each source cost?
> Shared antennas, power, processing, time references, networks, reference data, firmware and location can defeat apparent redundancy.

## single
What is a useful adversarial test for a resilient fusion design?
- Remove all sources simultaneously and check the system shuts down.
* Inject a plausible but biased source that is more confident than a correct independent source, and check the estimator identifies the inconsistency.
- Run the system only in open sky.
- Increase the update rate of every sensor.
> The test reveals whether a high-confidence bad measurement can pull the fused solution away from truth.

## single
A navigation subsystem correctly flags DEGRADED mode, but the autonomy stack ignores the flag and continues at full speed. What does this show?
- The navigation subsystem has failed its integrity requirement.
* Application-level resilience matters: the consumer must define and apply its own behaviour when PNT quality falls.
- Mode flags are unnecessary.
- The autonomy stack should average the flags.
> A resilient PNT subsystem cannot guarantee safety if the consuming application ignores its uncertainty and mode information.
